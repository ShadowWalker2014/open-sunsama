## How to self-host Open Sunsama with Docker

This quick start runs Open Sunsama on your own machine. You need Docker and about 2 GB of RAM. It takes one command, plus a few minutes for the first build.

**1. Get the code, then build and start everything.**

```bash
git clone https://github.com/ShadowWalker2014/open-sunsama.git
cd open-sunsama
docker compose up -d --build
```

This starts PostgreSQL, Redis, the API and the web app. The API creates its tables and its own secrets on first start, so a local trial needs no setup.

**2. Open the app.** Go to `http://localhost:3000` and create your account. Check the API with `curl http://localhost:3001/health`.

For a real server, set `API_URL`, `WEB_APP_URL` and `POSTGRES_PASSWORD` in `.env` before your first build. You will also want your own domain and HTTPS. The [Docker deployment guide](/docs/self-hosting/docker) covers the production setup, the reverse proxy and every setting.

### Features that need extra keys

Tasks, time blocks, rollover and the API work out of the box. A few features call outside services, so you add your own keys:

- **Google or Outlook calendar sync:** your own OAuth app keys.
- **File attachments:** any S3-compatible storage.
- **Email:** a Resend API key.
- **Push notifications:** VAPID keys.

### Connect your AI agent to your own server

Your instance serves an MCP server at `https://your-api-domain/mcp`. Add it in Claude, ChatGPT, Cursor or any MCP client, then sign in with OAuth. Set `API_URL` and `WEB_APP_URL` so the sign-in screen points at your domain.

After that, you can say "plan my afternoon" and watch the blocks appear. The talk goes between your agent and your server, with no relay in between. The [MCP overview](/docs/mcp/overview) has the setup for each client, and the [API reference](/docs/api/authentication) covers API keys.

## How to keep a self-hosted stack secure

Self-hosting removes the vendor. It also makes you the security team. These basics cover most of the risk.

1. **Use HTTPS.** Put Caddy, nginx or Traefik in front of every app. Never send a login over plain HTTP.
2. **Keep the database private.** Open Sunsama's compose file binds PostgreSQL and Redis to localhost only. Keep it that way, and check the same for every other app.
3. **Change default passwords.** Set your own database password before the first start.
4. **Put personal apps behind a VPN.** If only you use it, Tailscale or WireGuard keeps it off the open internet.
5. **Update on a schedule.** Pull and rebuild once a month, or when a release fixes a security bug.
6. **Turn off open sign-ups** on apps that allow it, once your accounts exist.

## How to back up your self-hosted apps

A backup you have never restored is a hope, not a backup. Use the 3-2-1 rule: three copies, on two kinds of storage, with one off-site.

For Open Sunsama, dump PostgreSQL every night:

```bash
docker compose exec -T postgres pg_dump -U opensunsama opensunsama | gzip > backup_$(date +%F).sql.gz
```

For SQLite apps like tududi and Trilium, stop the app or use its backup feature, then copy the database file. For Radicale, copy its data folder.

Then copy the files off the box, for example to another server or object storage. Once a quarter, restore one into a fresh container and check your tasks are there.

## Self-hosted vs cloud: which should you pick?

Self-host when you want full control, or when GDPR says your data must stay in one place. It also makes sense if you already run a home server. You trade a little time each month for owning everything.

Use a hosted version when you want to plan your day today and never think about servers. Open Sunsama, Vikunja and tududi run the same code in the cloud and on your box, so you can move later. On the hosted version, grab the [desktop apps](/download) too, and use the web app on your phone.
