The best self-hosted productivity app overall in 2026 is **Open Sunsama**. It is a task manager and daily planner with time blocking, and any AI agent can use it.

Add **Vikunja** or **Tududi** if you need shared task lists. Add **Radicale** or **Nextcloud** for your calendar, and **Joplin Server** or **Trilium** for notes.

All of them run on a small server or a home box, most with a single Docker command.

We build Open Sunsama, so we put it first — here is why, and where others fit better. A task list tells you what to do, and Open Sunsama also plans when you do it. If you need an MIT or GPL license, or shared team lists, Vikunja and Tududi fit better.

This guide shows what each app replaces, how to run Open Sunsama with Docker, and how to keep it all safe and backed up.

## Quick answer

- **Best overall:** [Open Sunsama](https://github.com/ShadowWalker2014/open-sunsama), a self-hosted task manager and planner with time blocking and MCP.
- **Self-hosted task lists under AGPL or MIT:** [Vikunja](https://vikunja.io), or [Tududi](https://tududi.com) if you want small and simple.
- **Self-hosted calendar:** [Radicale](https://radicale.org) for a tiny CalDAV server, or [Nextcloud](https://nextcloud.com) for a full suite.
- **Self-hosted notes:** [Joplin Server](https://joplinapp.org) for synced notes, or [Trilium](https://github.com/TriliumNext/Trilium) for a note tree.
- **No server at all:** [Super Productivity](https://super-productivity.com) syncs through WebDAV or its own sync server.

## What should you self-host?

Think in jobs, not apps. Most people need four things: a task list, a way to plan the day, a calendar and notes.

### Best overall: Open Sunsama, a self-hosted planner with time blocking

A to-do list tells you what to do. A planner tells you when. That is the gap people on r/selfhosted keep asking about: "So far I have not seen anything that comes close" to Sunsama.

Where it falls short:

- The license is non-commercial. Personal self-hosting is fine. Companies need a commercial license.
- It is one person's planner, not a team project tool.
- Calendar sync covers Google, Outlook and iCloud. There is no Nextcloud or CalDAV task sync yet.
- The ready-made desktop and mobile apps connect to the hosted service. To point them at your server, you build them yourself with your own API address.

### A self-hosted task manager: Vikunja or Tududi

If you want a plain task list instead, **Vikunja** is the closest thing to a self-hosted Todoist. It has list, kanban, Gantt and table views, CalDAV and a Todoist importer. Its weak spot is the phone: you use the web app, and native apps are still on the roadmap.

**Tududi** is smaller. One Docker command, one SQLite file, and a built-in MCP server with 59 tools. It has no calendar view, so it does not do time blocking.

Read our [open source Todoist alternatives](/blog/open-source-todoist-alternatives) for the full list.

### A self-hosted calendar: Radicale or Nextcloud

**Radicale** is a tiny CalDAV and CardDAV server. Point your phone and desktop calendar apps at it and you are done. It has no full web calendar of its own.

**Nextcloud** gives you a web calendar, files, contacts and tasks in one suite. It is a bigger server to run, but it does a lot.

### Self-hosted notes: Joplin Server or Trilium

**Joplin Server** syncs Joplin's apps on every device, with end-to-end encryption. Note that the server uses a personal-use license, while the apps are AGPL.

**Trilium** is a web app for a deep tree of notes. It suits people who want a private wiki.

## How to self-host Open Sunsama with Docker

This quick start runs Open Sunsama on your own machine. You need Docker and about 2 GB of RAM. It takes one command, plus a few minutes for the first build.

**1. Get the code.**

```bash
git clone https://github.com/ShadowWalker2014/open-sunsama.git
cd open-sunsama
```

**2. Build and start everything.**

```bash
docker compose up -d --build
```

This starts PostgreSQL, the API and the web app. The API creates its tables and its own secret on first start, so a local trial needs no setup.

**3. Open the app.** Go to `http://localhost:3000` and create your account. Check the API with `curl http://localhost:3001/health`.

For a real server, set `API_URL` and `WEB_APP_URL` in `.env` to your public addresses before you build. You will also want your own domain, HTTPS and a strong database password. The [Docker deployment guide](/docs/self-hosting/docker) covers the production setup, the reverse proxy and every setting.

### Features that need extra keys

Tasks, time blocks, rollover and the API work out of the box. A few features call outside services, so you add your own keys:

- **Google or Outlook calendar sync:** your own OAuth app keys, plus a calendar encryption key.
- **File attachments:** any S3-compatible storage.
- **Email:** a Resend API key.
- **Push notifications:** VAPID keys.

### Connect your AI agent to your own server

Your instance serves an MCP server at `https://your-api-domain/mcp`. Add it in Claude, ChatGPT, Cursor or any MCP client, then sign in with OAuth. Set `API_URL` and `WEB_APP_URL` in the API's environment so the sign-in screen points at your domain.

After that, you can say "plan my afternoon" and watch the blocks appear. The talk goes between your agent and your server, with no relay in between. The [MCP overview](/docs/mcp/overview) has the setup for each client, and the [API reference](/docs/api/authentication) covers API keys.

## How to keep a self-hosted stack secure

Self-hosting removes the vendor. It also makes you the security team. These basics cover most of the risk.

1. **Use HTTPS.** Put Caddy, nginx or Traefik in front of every app. Never send a login over plain HTTP.
2. **Keep the database private.** The sample compose file publishes PostgreSQL on port 5432 for local use. On a server, remove that port or block it with a firewall.
3. **Change default passwords.** Replace the sample database password and use a long random `JWT_SECRET`.
4. **Put personal apps behind a VPN.** If only you use it, Tailscale or WireGuard keeps it off the open internet.
5. **Update on a schedule.** Pull, rebuild and apply schema changes once a month, or when a release fixes a security bug.
6. **Turn off open sign-ups** on apps that allow it, once your accounts exist.

## How to back up your self-hosted apps

A backup you have never restored is a hope, not a backup. Use the 3-2-1 rule: three copies, on two kinds of storage, with one off-site.

For Open Sunsama, dump PostgreSQL every night:

```bash
docker compose exec -T postgres pg_dump -U opensunsama opensunsama | gzip > backup_$(date +%F).sql.gz
```

For SQLite apps like Tududi and Trilium, stop the app or use its backup feature, then copy the database file. For Radicale, copy its data folder.

Then copy the files off the box, for example to another server or object storage. Once a quarter, restore one into a fresh container and check your tasks are there.

## Self-hosted vs cloud: which should you pick?

Self-host when you want full control, or when GDPR says your data must stay in one place. It also makes sense if you already run a home server. You trade a little time each month for owning everything.

Use the hosted version when you want to plan your day today and never think about servers. Open Sunsama, Vikunja and Tududi run the same code in the cloud and on your box, so you can move later. On the hosted version, grab the [desktop apps](/download) too, and use the web app on your phone.
